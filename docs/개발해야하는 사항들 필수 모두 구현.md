# 실시간 보안 확장 설계 (해커톤: AI 모델 보안 / 프롬프트 인젝션 방어)

## 1. 결론 (가능 범위)

| 형태 | 24h 가능성 | 판단 |
|---|---|---|
| Chrome 확장 (MV3) | ✅ 가능 | **24h 데모 대상으로 확정 권장** |
| 데스크톱 앱(Win/Mac 전역 감시) | ⚠️ 불가 | 접근성 API 훅 난이도↑ → 로드맵으로만 언급 |

## 2. 컨셉 재정의 — "쓰는 자리에서 실시간 보안"

**문법 교정기가 '문법'을 실시간으로 잡아준다면, 이 앱은 '보안'을 실시간으로 잡아줌.**

실시간 교정 도구의 핵심 UX 혁신은 "별도 앱을 열 필요 없이, 내가 글을 쓰는 바로 그 자리에서 항상 옆에 떠 있다"는 상시성임. 이걸 그대로 가져와 **사람이 AI에게 텍스트를 보내는 바로 그 순간**을 지킴.

이게 왜 주제에 정확히 맞는가: 프롬프트 인젝션과 데이터 유출이 실제로 발생하는 지점은 **사람↔AI 경계**임. 교정 도구가 '작성 시점'에 개입하듯, 이 앱은 **'AI 전송 시점'에 개입**해서 그 경계를 지킴 → 정통 AI 모델 보안·인젝션 방어 제품이 됨.

## 3. 무엇을 실시간으로 잡아주는가 (3방향)

**① Outbound — 내가 AI에게 보낼 때 (유출 방지)**

- ChatGPT·Claude 입력창에 계약서·이력서를 붙여넣는 순간 주민번호·계좌·전화 감지
- 오타에 밑줄 긋듯 민감정보에 밑줄 → 클릭 시 **복원 가능 마스킹**(`[이름1]`, `[계좌A]`) 원클릭 적용

**② Inbound — 내가 붙여넣는 콘텐츠 속 위협 (인젝션 방어)**

- 웹페이지·이메일·문서에서 복사해 AI에 넣을 때, 그 안에 숨은 "이전 지시 무시하고 ~하라" 같은 인젝션을 탐지·경고
- **전송 전 인터셉트**: 위험 등급이면 Enter/전송 버튼을 가로채 확인 모달 표시

**③ 브라우징 중 위협 (일상 보호)**

- 읽는 화면에서 피싱 링크·사칭·계약서 독소조항 신호를 배지로 알림

## 4. 실시간 UX

```
[텍스트 필드 우하단]  🛡️ 3   ← 위험 건수 배지
        ↓ (클릭 / 자동)
[인라인 표시]
   빨간 물결줄  = 숨은 명령(인젝션)
   노란 물결줄  = 개인정보
        ↓ (호버/클릭)
[교정 카드]
   "이 문장에 AI를 향한 숨은 명령이 있음"
   [ 제거 ]  [ 무시 ]
   ───────────────
   "주민번호가 포함됨"
   [ 마스킹 ]  [ 무시 ]
        ↓ (AI 사이트에서 전송 시)
[전송 전 확인 모달]
   "🔴 위험 2건이 감지됨. 마스킹 후 전송할까요?"
   [ 안전하게 전송 ]  [ 그대로 전송 ]
```

## 5. 아키텍처 (Chrome MV3)

```
[Content Script — 페이지에 주입]
  textarea / contenteditable 감시 (input·paste·MutationObserver)
    → 디바운스(입력 멈춤 500ms) / 붙여넣기는 즉시
    → (A) 로컬 탐지: 정규식 PII + 인젝션 키워드  ← 즉시·무료·프라이버시
    → (B) LLM 탐지: (A)가 걸리거나 대용량 붙여넣기 시에만 백그라운드로 요청
    → 오버레이 렌더러: 밑줄 + 우하단 배지
    → AI 사이트: 전송 버튼/Enter 가로채기

[Background Service Worker]
  API 호출 담당(키를 페이지에 노출 안 함) · 결과 캐싱

[자체 백엔드(프록시)]
  LLM 판별·요약 호출 (확장에 API 키를 넣지 않기 위한 경유지)

[Popup / Options]
  on·off 토글 · 사이트별 설정 · 차단 로그
```

탐지 2계층은 이전 통합 엔진과 동일 구조라 **백엔드 로직을 그대로 재사용**함. 즉 이번 확장은 카메라 앱과 같은 엔진에 얹은 또 하나의 '프론트'일 뿐임 → 엔진 투자분이 낭비되지 않음.

## 6. 24h 현실 스코프 & 최대 난관

가장 어려운 부분은 **임의 사이트에서의 인라인 밑줄 오버레이**임(상용 교정 도구들이 수년 투자한 지점). 24h에서는 아래로 스코프를 잘라야 함.

- **타깃 사이트 정밀 지원(인라인 밑줄):** ChatGPT·Claude 등 DOM이 알려진 1~2개 사이트에 한해 밑줄+전송 인터셉트 완성
- **범용 폴백(배지+패널):** 그 외 모든 텍스트 필드에서는 밑줄 대신 **우하단 배지 + 위험 목록 패널**만 제공 (구현 난이도↓, 커버리지↑)
- 데스크톱 전역 감시, 다중 언어 전면 지원은 로드맵

프라이버시 설계도 곧 세일즈 포인트임: 로컬 우선 탐지 + 필요 시에만 클라우드 + 복원 마스킹으로 **원본 개인정보는 밖으로 안 나감** → "보안 앱이니 우리부터 프라이버시 우선" 서사.

## 7. 데모 시나리오

- **유출 차단:** 회사원이 계약서를 ChatGPT에 붙여넣는 순간 주민번호에 밑줄 → 원클릭 마스킹 후 전송(before/after diff 시연)
- **인젝션 차단:** 악성 웹페이지에서 복사한 텍스트를 AI에 붙여넣자 숨은 명령을 밑줄로 드러내고 전송 전 모달로 차단
- **일상 보호:** 카톡 웹/메일에서 피싱 문구에 배지 경고

## 8. 시간 배분 (권장)

| 구간 | 작업 |
|---|---|
| 0~2h | 확장 스캐폴딩(MV3) · 악성 샘플 준비 |
| 2~6h | Content Script 입력·붙여넣기 감시 + 로컬 PII/인젝션 탐지 |
| 6~10h | 백그라운드 프록시 + LLM 판별 연동 |
| 10~15h | 배지 + 교정 카드 UI + 마스킹 원클릭 |
| 15~19h | ChatGPT 타깃 인라인 밑줄 + 전송 전 인터셉트 |
| 19~22h | 데모 폴리싱 · before/after · 프라이버시 데모 |
| 22~24h | 피치 리허설 · 버퍼 |

---

*정리: "문법이 아니라 보안을 실시간으로"라는 한 줄이 심사에서 즉시 이해되고, 주제 정합성(AI 전송 시점 인젝션·유출 방어)도 정통으로 맞음. 카메라 앱과 엔진을 공유하므로 둘 중 하나로 확정하거나, 엔진 1개 + 프론트 2개(모바일 카메라 / 크롬 확장)로 밀어도 됨.*
