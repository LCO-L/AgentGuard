## 2. New architecture concept: X-AG-Client (required reading for the next worker)

**Problem**: rug-pull fingerprints used the filename as a global key → A's `report.pdf` and B's different `report.pdf` triggered false "tampering detected" alarms. History (`/v1/scans`) was also shared across all users → other people's filenames were exposed in the public demo.

**Solution**: without accounts — the browser/extension generates a random ID once and sends it on every request as the `X-AG-Client` header.

- Where it's generated: `ui/agconfig.js` `clientId()` (localStorage `ag_client_id`) · `extension/background.js` `getCfg()` (chrome.storage)
- Validation: `api/deps.py` `ag_client` — if not `[A-Za-z0-9_-]{1,64}`, then `""` (global = old behavior, CLI backward-compat)
- Rug-pull key: `client|filename` (`core/ai/rugpull.py`)
- History: records store a `client` field; queries filter to your own (`services/history_service.py`)
- **Enterprise-mode hook (BM)**: only when `AG_API_KEY` is set does `/v1/scans?scope=all` allow the full audit view — the demo gets 403. The "all-employee audit log = paid tier" structure is implemented in code (`api/routes/history.py`)

⚠️ Old history records (no client field) are invisible from browsers — they appear only in headerless queries (CLI). This is intended behavior.

## 3. Operating rules (important)

1. **Keep uvicorn at 1 worker** (current Procfile/railway.json as is). The file-store lock is per-process, so `--workers 2+` re-introduces races. If traffic grows, migrating to SQLite is the prerequisite.
2. Concurrency: FastAPI thread pool (default 40). With LLM judgment at ~20s, dozens of simultaneous users are OK; overflow waits (doesn't hang).
3. Manual on-device model prep: `ollama pull hf.co/unsloth/Qwen3-4B-Instruct-2507-GGUF:Q4_K_M` (~2.5GB). The engine already handles `num_ctx=8192` · `temperature 0` · `think:false`.
4. Key environment variables: `AG_AI_PROVIDER` · `AG_OLLAMA_MODEL` · `AG_API_KEY` (unlocks enterprise mode) · `AG_HISTORY_PATH` · `AG_CACHE_DIR`
