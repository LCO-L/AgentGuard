# 💼 AgentGuard for Enterprise — AI 입력 단계의 실시간 DLP

> **한 줄:** 직원이 ChatGPT·Claude·Copilot 같은 LLM에 **개인정보·회사기밀·소스코드**를 붙여넣기 **전에** 탐지하고, 되돌릴 수 있게 가려주고, 더 조심하도록 코치합니다.

## 1. 누가 사는가 (구매 결정자)

| 역할 | 사는 이유 |
|---|---|
| **CISO·정보보안 책임자** | LLM 사용 통제·유출 방지·감사 근거가 필요 |
| **경영진(CEO/COO)** | 생산성(AI 활용)은 살리면서 사고 리스크는 줄이고 싶음 |
| **개인정보보호책임자(CPO)·법무** | 개인정보보호법·GDPR·계약상 기밀 유지 의무 준수 |
| **IT/플랫폼팀** | 조직 전체 배포·정책·리포팅을 한 곳에서 |

## 2. 왜 지금 (Why now)

- 직원의 **일상적 LLM 사용**이 폭증 → 붙여넣기 한 번에 기밀이 외부 모델로 전송
- 실제 사고 다수(소스코드·회의록·고객정보를 챗봇에 입력) → **입력 단계 통제 부재**가 근본 원인
- 규제·계약 압박(개인정보보호법, GDPR, 고객사 보안 요구)
- 기존 DLP는 파일·이메일 중심이라 **"LLM 입력창"이라는 새 통로를 못 막음** → 여기가 빈틈

## 3. 이미 그걸 하는 제품 (현재 기능 → 기업 가치 매핑)

| 기업이 원하는 것 | AgentGuard가 지금 하는 것 |
|---|---|
| **보내기 전 탐지** | 보안 에디터·익스텐션 `inputguard`가 LLM 입력창을 가로채 **전송 전** 검사 |
| **기밀을 지우되 일은 계속** | **되돌릴 수 있는 마스킹** — 원본은 기기에, AI엔 `[SECRET_1]`·`[RRN_1]`만. 응답 받으면 로컬에서 원복 |
| **무엇을 잡나** | API키·토큰 24종(AWS·GitHub·Slack·Stripe…), 주민번호·연락처 등 PII, 프롬프트 인젝션 17종, 취약코드 17종 |
| **원본이 밖으로 안 나가야** | **온디바이스(Ollama)** 모드 — 판단까지 회사 기기 안에서. 클라우드 전송 0 |
| **누가·언제 무엇을** | 익스텐션 검사/차단 **기록(로그)** = 감사 추적의 씨앗 |
| **직원 교육 효과** | 밑줄 + "왜 위험한지" 쉬운 설명 = **행동을 바꾸는 코칭** |
| **우회 차단** | 제로폭·호모글리프·이모지 스테가노그래피까지 정규화 후 탐지 — 상용 가드레일이 놓치는 것 |

## 4. 차별점 (왜 우리를 사는가)

1. **온디바이스 우선** — 검사하려고 데이터를 또 다른 클라우드로 보내지 않음(프라이버시 역설 해결)
2. **되돌릴 수 있는 마스킹** — 차단이 아니라 "가리고 계속" → 생산성을 죽이지 않음(도입 저항↓)
3. **시나리오 레지스트리** — 새 위험 = 규칙 한 줄. 회사별 기밀 패턴(사번·내부코드명)을 즉시 추가
4. **여러 프런트, 한 엔진** — 설치형·크롬 확장·APK·(예정)VS Code. 같은 로직을 어디서나

## 5. 기업 판매를 위한 로드맵 (엔터프라이즈 에디션)

> 지금은 개인/데모가 완성형. 아래는 조직 판매 시 추가되는 상위 계층(있으면 계약이 커짐).

| 기능 | 설명 | 난이도 |
|---|---|---|
| **관리자 정책(조직 규칙팩)** | 회사 전용 탐지 규칙·차단 강도를 중앙에서 배포 | 중 (레지스트리 확장) |
| **중앙 감사 로그·대시보드** | 부서별 위험 추이, 유형별 통계, 리포트 | 중~상 |
| **강제 배포(MDM/GPO)** | 크롬 확장·설치형을 조직 전체에 강제 설치 | 하(엔터프라이즈 정책) |
| **SSO/역할** | 관리자/일반, SAML·OIDC | 중 |
| **차단 모드** | 특정 등급은 경고가 아닌 **전송 차단** | 하(현 로직에 스위치) |
| **온프레미스 배포** | 백엔드+Ollama를 사내망에 — 폐쇄망 반입·검증 절차 문서화 완료([`AIRGAP.md`](AIRGAP.md)) | 하(이미 단일 백엔드) |

## 6. 세일즈 한 문장 (피치)

> "직원들은 계속 AI를 쓰게 두세요. AgentGuard가 **붙여넣기 직전**에 개인정보·기밀·키를 알아서 가려주고, 원본은 회사 기기 밖으로 한 글자도 내보내지 않습니다. **AI 입력 단계의 실시간 보안 가드**입니다."

### 데모에서 강조할 순서 (기업 청중용)
1. 보안 에디터에 "김민수 주민번호 900101-1234567, AWS키 AKIA…" 붙여넣기 → **실시간 밑줄 + 마스킹 미리보기**
2. 그대로 "AI에 전송" → AI엔 `[RRN_1]`·`[SECRET_1]`만 간다는 걸 보여주기
3. **온디바이스 토글** → "원본은 이 기기 밖으로 안 나갑니다" 강조
4. 익스텐션으로 실제 ChatGPT 입력창에서 동일 탐지
5. 기록(로그) 탭 → "감사 추적이 됩니다"

## 7. 오픈소스(MIT)와 BM의 공존 — 오픈코어

- **코어는 MIT 공개**: 엔진·탐지·마스킹·UI 전부. 공개 = 신뢰(코드를 볼 수 있는 보안 도구) + 유통(개발자 입소문) + 채용/커뮤니티.
- **돈은 기업 계층에서**: 경영진·보안책임자가 사는 건 코드가 아니라 **통제와 기록** —
  직원이 AI/외부에 입력하기 *전* 기밀·개인정보를 탐지·마스킹·차단(차단 모드),
  조직 전용 민감어(orgTerms), 전 직원 감사 로그·CSV 리포트, 중앙 정책 배포, SSO, 온프레미스, SLA.
- **BYOK 원칙**: AI 키는 고객이 자기 것을 씀. 우리는 키·원문·매핑을 저장하지 않음 → 도입 심사가 빨라짐.
- 이미 구현된 씨앗: 차단 모드 · 회사 민감어 · `/audit` 감사 대시보드(필터·CSV) · 단일 백엔드 온프레미스 배포.
