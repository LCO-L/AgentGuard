## 2. 새 아키텍처 개념: X-AG-Client (다음 작업자 필독)

**문제**: 러그풀 지문이 파일명 전역 키 → A의 `report.pdf`와 B의 다른 `report.pdf`가 "변조 감지" 거짓 경보. 이력(`/v1/scans`)도 전 사용자 공유 → 공개 데모에서 남의 파일명 노출.

**해법**: 계정 없이 — 브라우저/확장이 최초 1회 랜덤 ID 생성 후 모든 요청에 `X-AG-Client` 헤더로 전송.

- 생성 위치: `ui/agconfig.js` `clientId()` (localStorage `ag_client_id`) · `extension/background.js` `getCfg()` (chrome.storage)
- 검증: `api/deps.py` `ag_client` — `[A-Za-z0-9_-]{1,64}` 아니면 `""`(전역=기존 동작, CLI 하위호환)
- 러그풀 키: `클라이언트|파일명` (`core/ai/rugpull.py`)
- 이력: 레코드에 `client` 필드 저장, 조회 시 본인 것만 필터 (`services/history_service.py`)
- **기업 모드 연결(BM)**: `AG_API_KEY` 설정 시에만 `/v1/scans?scope=all` 전체 감사 뷰 허용 — 데모는 403. "전 직원 감사 로그 = 유료 계층" 구조가 코드로 구현됨 (`api/routes/history.py`)

⚠️ 기존 이력 레코드(client 필드 없음)는 브라우저에서 안 보인다 — 헤더 없는 조회(CLI)에서만 보임. 의도된 동작.

## 3. 운영 수칙 (중요)

1. **uvicorn 워커는 1개 유지** (현 Procfile·railway.json 그대로). 파일 저장소 lock이 프로세스 단위라 `--workers 2+`면 레이스 재발. 트래픽 커지면 SQLite 전환이 선행조건.
2. 동시 처리: FastAPI 스레드풀(기본 40). LLM 판단 ~20초 기준 동시 수십 명 OK, 초과분은 대기(멈춤 아님).
3. 온디바이스 모델 수동 준비: `ollama pull hf.co/unsloth/Qwen3-4B-Instruct-2507-GGUF:Q4_K_M` (~2.5GB). 엔진은 `num_ctx=8192`·`temperature 0`·`think:false` 이미 처리.
4. 주요 환경변수: `AG_AI_PROVIDER` · `AG_OLLAMA_MODEL` · `AG_API_KEY`(기업 모드 잠금해제) · `AG_HISTORY_PATH` · `AG_CACHE_DIR`
