## 0. 먼저 결정할 결론

### 권고 결론

SecureType은 **보안 전담자가 없는 바이브 코더가 프롬프트·코드·설정·문서를 AI에 보내기 직전, 위험한
구간을 밑줄로 표시하고 이유와 수정안을 보여주는 보안 코치**다.

해커톤 MVP는 브라우저 확장이나 IDE 플러그인이 아니라 **단일 웹 보안 에디터**로 만든다. 지원 범위는
다음 네 가지 룰팩으로 제한한다.

## 1. 왜 이 제품인가

### 핵심 문제

바이브 코더는 보안 전문가가 아니지만 AI가 만든 결과를 실제 서비스에 연결한다. 이 과정에서 다음 순
간이 반복된다.

- `.env`, API 키, 고객 정보가 섞인 내용을 AI에 그대로 붙여 넣는다.
- AI가 제안한 `eval`, 문자열 결합 SQL, CORS 전체 허용 코드를 빠르게 채택한다.
- 에이전트에게 `production DB를 정리하고 배포해 줘`처럼 넓고 파괴적인 권한을 준다.
- README, 이슈, 웹 문서 안의 악성 지시를 에이전트가 신뢰할 수 있는 명령으로 받아들인다.
- 위험하다는 느낌은 있지만 무엇을 어떻게 고쳐야 하는지 알기 어렵다.

문제는 “보안 검사를 전혀 할 수 없다”가 아니다. 기존 도구는 주로 저장소, 커밋, PR, CI 단계에서 작동
하고 결과도 보안 지식을 전제한다. SecureType이 차지할 순간은 **AI에게 보내기 바로 전**이다.

### 대표 사용자

**보안 전담자 없이 AI로 웹 서비스를 만들고 배포하려는 초기 창업팀 개발자**

| 항목 | 내용 |
| --- | --- |
| 목표 | AI의 속도를 유지하면서 치명적인 보안 실수를 배포 전에 줄인다. |
| 행동 | 프롬프트, 생성 코드, `.env` 일부, README, shell 명령을 AI 채팅이나 에이전트에 자주 붙여 |
| 넣는다. |  |
| 제약 | 보안 용어에 익숙하지 않고 별도 스캐너를 설정할 시간이 부족하다. |
| 불안 | “이 키를 보내도 되나?”, “이 코드를 실행해도 되나?”, “에이전트에게 권한을 너무 많이 줬나?” |
|  |  |
| 현재 대안 | 눈으로 확인, AI에게 다시 질문, 커밋 후 스캐너 경고, 문제가 생긴 뒤 키 교체 |
| 성공 신호 | 10초 안에 위험 위치·이유·안전한 수정안을 이해하고 다음 행동을 결정한다. |

### 보조 사용자

- 계약서·회의록·고객 문서를 AI에 붙여 넣는 직장인
- 이력서와 포트폴리오를 AI로 고치는 취준생
- 외부 문서와 고객 메모를 자주 요약하는 프리랜서

보조 사용자는 개인정보 마스킹과 문서 인젝션 룰팩의 확장성을 보여주되, MVP 메시지의 중심은 **바이브
코더**로 유지한다.

### Jobs-to-be-Done

> AI에 프롬프트·코드·설정·문서를 보내려 할 때, 위험한 부분과 그 이유를 즉시 확인하고 안전한 대안으
로 고치고 싶다. 그래야 개발 속도를 크게 늦추지 않으면서도 어떤 위험을 수용했는지 설명할 수 있다.

## 2. 제품 정의

### 가치 제안

| 사용자가 원하는 것 | SecureType이 제공하는 것 | 사용자에게 보이는 증거 |
| --- | --- | --- |
| 비밀정보를 보내지 않기 | 키·토큰·PII 후보 탐지와 마스킹 제안 | 위험 구간 밑줄, 마스킹 전후 diff |
|  |  |  |
| 취약한 코드를 그대로 쓰지 않기 | 고신뢰 취약 패턴과 안전한 수정 예시 | 문제 위치, 쉬운 설명, 수 |
| 정 preview |  |  |
| 에이전트에 과도한 권한을 주지 않기 | 파괴적 명령·민감 데이터와 외부 전송 조합 경고 | 권한 경로와 |
| 최소 권한 제안 |  |  |
| 문서 속 악성 지시를 실행하지 않기 | 비신뢰 문서 지시의 출처 표시와 격리 | 의심 문구, 출처, 차단 |
| 이유 |  |  |
| 보안 때문에 흐름을 잃지 않기 | 입력 중 자동 검사와 한 번의 명시적 선택 | 적용·직접 편집·이번만 |
| 허용 |  |  |

### 제품 원칙

1. **AI 전송 직전:** 저장소 전체보다 지금 보내려는 입력을 먼저 지킨다.
2. **설명 먼저:** 경고 코드보다 “무엇이 왜 위험하고 어떻게 고치는가”를 보여준다.
3. **규칙이 근거, AI는 보조:** 정적 규칙이 탐지 근거를 만들고 LLM은 문맥 판별·설명·수정안을 보조한
다.
4. **사람이 최종 결정:** 수정은 preview로만 제안하며 사용자의 승인 없이 적용하지 않는다.
5. **원문 최소화:** 원문, 비밀값, 토큰 매핑을 서버 로그에 남기지 않는다.
6. **안전하게 실패:** 파서·정책·핵심 검사에 실패하면 외부 AI 전송을 진행하지 않는다.
7. **범위를 정직하게:** “보안 전반”이나 “100% 탐지”를 약속하지 않는다.

### 명시적 비목표

- 전체 저장소·네트워크·클라우드·패키지 CVE·비즈니스 로직 분석
- 완전한 SAST, DLP, EDR 또는 기업 프록시 대체
- 모든 언어와 프레임워크 지원
- 무승인 자동 수정 또는 AI 단독 차단 결정
- 브라우저 확장, IDE 플러그인, OS 전역 프록시의 MVP 구현
- 실제 API 키·개인정보·회사 기밀을 사용한 데모
- 검증되지 않은 시장 규모, 인수 금액, 법률 의무를 확정적 사업 근거로 제시

## 3. 실시간 코치형 핵심 UX

### 사용자 흐름

```
붙여 넣기/입력
    ↓  입력 중지 500ms
로컬 규칙 우선 검사
    ↓
위험 구간 밑줄 + 우측 경고 카드
    ↓
규칙 결과 즉시 표시 ── 선택적 LLM 문맥 설명이 뒤이어 보강
    ↓
수정 미리보기(diff)
    ↓
[수정 적용] [직접 편집] [이번만 허용]
    ↓
Critical 해소 또는 사유 있는 override 후 전송
```

### 실시간의 정의

- 붙여 넣기 직후 또는 마지막 입력 후 **500ms**에 자동 검사를 시작한다.
- 규칙 결과는 네트워크 응답을 기다리지 않고 먼저 보여준다.
- 선택적 LLM이 느리거나 실패하면 `rule-only` 상태를 명시하고 핵심 정책은 유지한다.
- MVP 측정 목표는 로컬 규칙 결과 **1초 이내**, 전체 결과 중앙값 **3초 이내**다. 제품 SLA가 아닌 데
모 목표다.
